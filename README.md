# Cyrius Stream Control v5.13.5

## Новое в v5.13.5

В «Источники» добавлен фильтр `ВСЕ серверы / CDN`. Кнопка ручной проверки теперь следует выбранному серверу; при `ВСЕ` проверяются все включённые CDN. Фоновая проверка источников не включается.

## Новое в v5.13.5

### Hotfix Flussonic 23: Static / On demand переживает restart

- Массовые кнопки `Static` / `On demand` больше не отправляют короткий `{"static": ...}` payload.
- Панель читает полный `config_on_disk`, меняет только поле `static` и отправляет полный сохранённый конфиг обратно.
- После PUT панель обязательно делает повторный GET и проверяет `config_on_disk.static`.
- Дополнительно сравнивается остальная конфигурация, чтобы при смене режима не потерялись inputs/title/provider/on_play и другие поля.
- Если Flussonic принял запрос, но не сохранил режим на диск, операция возвращает ошибку и не считается успешной.
- Та же защита добавлена в старое окно `Массовые операции → set_static`.

### Из v5.13.2: Telegram при `error/offline`

- Фоновая проверка использует только Flussonic `/streamer/api/v3/streams`; `ffprobe` и открытие input/source URL не используются.
- Событие `Поток error / offline` отправляется один раз при переходе в ошибку.
- Событие `Поток восстановлен` отправляется после выхода из ошибки.
- `ondemand waiting` и `disabled` не считаются аварией.
- В Гибридном режиме Assigned-поток проверяется только на назначенном CDN.

Тёмная админ-панель для управления несколькими Flussonic Media Server.

## Новое в v5.13.1

- Точный набор `N` немигрированных каналов на выбранный CDN: `Взять N → Выбрать N → Перенести сейчас`.
- Число N — это сколько **добавить**, а не общий лимит сервера.

- **Глобальный режим панели в Настройках**: две явные кнопки `Зеркальный` и `Гибридный`.
- В **Зеркальном** режиме раздел Размещение скрывается, формы создания/редактирования и M3U-импорт не предлагают Assigned CDN, а синхронизация работает как зеркало по всем включённым CDN.
- В **Гибридном** режиме автоматически возвращаются Размещение, Assigned, миграции, rollback и постпроверка.
- Переключение в Зеркальный режим **не удаляет** сохранённые назначения — они остаются в базе и снова становятся активными при возврате в Гибридный.
- В разделе **Потоки** в списке серверов появилась категория **ВСЕ**. Она объединяет одинаковые имена потоков со всех CDN в одну строку и показывает, на скольких серверах канал реально присутствует.
- В режиме **ВСЕ** Preview/Диагностика/Карточка выбирают конкретный CDN с потоком автоматически; изменение порядка отключено, пока не выбран конкретный сервер.
- Если один CDN недоступен, `ВСЕ` показывает данные с доступных серверов и отдельно сообщает о частичной загрузке.

## Новое в v5.12.1

- **Проверка после миграции** из таблицы истории: кнопка `✓ Проверить` вручную читает реальную конфигурацию на всех CDN.
- Для каждого канала показывается ожидаемый target CDN и фактическое наличие/отсутствие на каждом сервере.
- Отдельно выделяются `лишняя копия`, `назначен · отсутствует`, недоступный CDN и несовпадение конфигурации target со снимком до миграции.
- Для проблемного канала доступна кнопка **Исправить**: она открывает новый Dry Run и только после подтверждения повторяет безопасную миграцию на назначенный CDN.
- Из окна проверки можно сразу открыть **Карточку канала** или перейти к **Rollback всей миграции**.
- Постпроверка запускается только вручную; фонового опроса потоков не добавлено.

## Новое в v5.12.0

- **Rollback всей миграции одной кнопкой**.
- Перед каждой новой миграцией панель сохраняет полный снимок: размещение и конфигурацию потока на каждом включённом CDN.
- В разделе **Размещение** появилась таблица **История миграций**.
- Кнопка **↶ Откатить** сначала открывает Dry Run и показывает, что будет восстановлено/удалено.
- Во время rollback панель делает backup текущего состояния перед перезаписью или удалением.
- Откат возвращает не только потоки, но и прежний режим размещения (`Mirror`/`Assigned`).
- Частичный откат можно запустить повторно; миграция помечается полностью откатанной только после 100% успеха.
- Снимки создаются для миграций, выполненных на v5.12.0 и новее; старые миграции v5.11.x автоматически откатить всей пачкой нельзя.

## Новое в v5.9.3

- быстрый переключатель `On demand / Static` для каждого потока;
- массовые кнопки `On demand` и `Static` для отмеченных потоков;
- выбор режима по умолчанию прямо в M3U-импорте;

### Массовый импорт M3U

- Вставка обычного M3U/M3U8 текста прямо в панели.
- Используются только отображаемое название канала из `#EXTINF` и следующая строка URL.
- `tvg-id`, `tvg-logo`, `group-title`, `tvg-chno` и другие атрибуты игнорируются.
- Автоматически генерируется безопасное системное имя Flussonic, включая транслитерацию кириллицы.
- Предпросмотр перед записью: название, системное имя, URL и отметка уже существующих потоков.
- Повторы внутри одного M3U пропускаются.
- Уже существующие потоки по умолчанию не перезаписываются; обновление включается отдельной галочкой.
- При импорте можно выбрать зеркальную модель или назначить все импортируемые каналы на один CDN.
- Импорт выполняется только по запросу пользователя и ограничивает параллелизм, чтобы не создавать всплеск запросов к старым Flussonic.

### Раздел Cluster

Панель поддерживает отдельную конфигурацию load balancer и peer-серверов:

- зашифрованное хранение `cluster_key`;
- выбор Flussonic-сервера, который выполняет роль load balancer;
- режимы `clients`, `bitrate`, `usage` и `streams`;
- список peer с отдельным hostname;
- необязательный `max_bitrate` для каждого peer;
- генерация готового фрагмента `flussonic.conf`;
- таблица `Host`, `CPU`, `Mem`, `Clients`, `Streams`, `Output bitrate`, `Load`, `Uptime`.

Источники метрик:

- CPU, RAM, load average и uptime — Node Exporter;
- Clients — Flussonic sessions API;
- Streams и output bitrate — Flussonic streams API.

Поэтому Cluster работает со старыми версиями Flussonic, у которых нет современного runtime metrics API.

> Панель не перезаписывает `flussonic.conf` автоматически. Для старых установок конфигурация генерируется для ручного применения после резервной копии.

### Исправление умной синхронизации

Сравнение больше не считает различиями:

- `position`;
- runtime-статистику;
- `named_by` и другие служебные поля;
- разное представление `input` и `on_play` в старых и новых API.

Для настоящих отличий рядом с сервером отображаются конкретные поля, например `inputs`, `provider` или `on_play`.

## Ручная проверка источников

Панель не создаёт фоновую задачу проверки input. Открытие раздела **Источники** только читает последние сохранённые результаты из базы. Сетевые запросы к HLS/HTTP/M4F выполняются исключительно после нажатия **Проверить все сейчас** или **Проверить** возле конкретного потока.

Старые параметры `SOURCE_CHECK_ENABLED` и `SOURCE_CHECK_SECONDS` сохранены в `.env.example` для совместимости, но не включают планировщик.

## Обновление с предыдущей версии без rsync

Архив загрузите как `/root/flussonic-panel-v5.13.5.zip`, затем запустите поставляемый скрипт:

```bash
rm -rf /tmp/flussonic-panel-v5135-installer
mkdir -p /tmp/flussonic-panel-v5135-installer
unzip -q -o /root/flussonic-panel-v5.13.5.zip -d /tmp/flussonic-panel-v5135-installer
bash /tmp/flussonic-panel-v5135-installer/flussonic-panel/upgrade-from-zip.sh
```

Скрипт сохраняет `.git` и `.env`, не использует `rsync`, пересобирает отдельный образ `flussonic-panel:v5135` и оставляет Docker volume `flussonic-panel-data` без изменений.

Не удаляйте volume и не меняйте `PANEL_SECRET_KEY`.

## Настройка Cluster

1. Добавьте load balancer и CDN-узлы в разделе **Серверы**.
2. Для CDN-узлов настройте Node Exporter URL.
3. Откройте **Cluster → Настроить**.
4. Выберите balancer-сервер.
5. Укажите имя balancer, режим и `cluster_key`.
6. Отметьте peer-серверы и проверьте их hostname.
7. Сохраните и нажмите **Показать конфиг**.
8. Сделайте backup `flussonic.conf`, примените конфиг вручную и перезапустите Flussonic.

Пример генерируемого конфига:

```text
cluster_key CHANGE_ME;

peer cdn-1.example.com {
}
peer cdn-2.example.com {
}

balancer lb01 {
  mode clients;
  server cdn-1.example.com;
  server cdn-2.example.com;
}
```

## Node Exporter

На каждом Flussonic-сервере:

```bash
apt-get update
apt-get install -y prometheus-node-exporter
systemctl enable --now prometheus-node-exporter
```

Разрешите порт только IP панели:

```bash
ufw allow from IP_СЕРВЕРА_ПАНЕЛИ to any port 9100 proto tcp
```
